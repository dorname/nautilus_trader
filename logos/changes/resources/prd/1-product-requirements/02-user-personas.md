# 用户画像（User Personas）

> 状态：基线 · 来源：README.md 用户章节、docs/tutorials、docs/how_to 使用场景逆向归纳

## P1 · 量化研究员（Quant Researcher）

- **背景**：金融/加密领域研究员，Python 熟练，关注因子验证与策略原型
- **目标**：在真实历史数据上快速回测策略，得到可复现的绩效报告
- **使用方式**：Python 编写 Strategy，用 BacktestNode/BacktestEngine 跑历史数据，产出 Portfolio 绩效分析
- **关键诉求**：回测确定性（同一输入同一结果）、多场所数据接入（databento/tardis 历史数据）、绩效指标完整
- **成功标准**：策略代码不加修改即可进入模拟/实盘验证
- **对应需求**：FR-002 确定性回测、FR-014 历史数据回放、FR-012 绩效分析

## P2 · 量化开发者（Quant Developer）

- **背景**：软件工程师，Rust/Python 双栈，负责把研究员的策略工程化
- **目标**：构建可长期运行、可监控、可故障恢复的实盘交易节点
- **使用方式**：Rust 编写性能关键型策略或自定义组件；Python 做配置与编排；部署 LiveExecNode
- **关键诉求**：事件溯源可审计、崩溃后状态恢复、消息总线可观测、低延迟
- **成功标准**：节点 7×24 稳定运行，崩溃重启后订单/仓位状态一致
- **对应需求**：FR-004 事件溯源、FR-005 崩溃恢复、NFR-001 延迟、NFR-005 可观测性

## P3 · 自营交易团队（Prop Trading Team）

- **背景**：小型到中型交易公司/自营团队，自建交易基础设施
- **目标**：以开源引擎替代自研系统，覆盖多场所执行与风控
- **使用方式**：集成多个 venue 适配器，统一 Portfolio 与风控引擎管理多账户多策略
- **关键诉求**：多场所统一抽象（同一 API 操作不同交易所）、集中风控（RiskEngine 预检）、许可证友好（LGPL-3.0）
- **成功标准**：多场所订单生命周期管理一致，仓位/账户核算准确
- **对应需求**：FR-001 多资产多场所、FR-003 统一订单生命周期、FR-008 集中风控、FR-009 组合核算

## P4 · 适配器贡献者（Adapter Contributor）

- **背景**：开源社区开发者，为尚未支持的 venue 编写适配器
- **目标**：为新的交易所/数据源实现 DataClient/ExecutionClient
- **使用方式**：参照 `crates/adapters/sandbox` 与既有 18 个适配器，实现端口 trait，经 testkit 验证
- **关键诉求**：端口适配器架构清晰、testkit 提供回放测试工具、贡献流程（CONTRIBUTING.md）明确
- **成功标准**：新适配器通过 CI 全量测试并被合入主干
- **对应需求**：FR-013 适配器框架、FR-016 测试工具包
