# 用户故事（User Stories）

> 状态：基线 · 格式：作为〈角色〉，我想〈能力〉，以便〈价值〉；验收条件可追溯到 FR/NFR

## US-001 确定性回测
**作为**量化研究员，**我想**在历史数据上运行策略并得到逐事件可复现的回测结果，**以便**验证策略逻辑本身而非环境噪声。
验收：同一配置与数据集重复回测，产出的事件流与绩效完全一致（FR-002，NFR-003）。

## US-002 回测转实盘零改动
**作为**量化开发者，**我想**把回测通过的 Strategy 原样切换到实盘节点运行，**以便**消除研究到生产的重写成本与行为漂移。
验收：策略类同时被 BacktestNode 与 LiveExecNode 加载，代码路径一致（FR-002、FR-010）。

## US-003 多场所统一操作
**作为**自营交易团队，**我想**用同一套订单/行情 API 操作多个交易所（Binance、Bybit、OKX、IB 等），**以便**避免为每个场所维护私有代码。
验收：18 个适配器共享统一 Venue/Instrument/Order 抽象；同一 Strategy 可订阅多场所数据并下单到多场所（FR-001、FR-013）。

## US-004 订单全生命周期管理
**作为**量化开发者，**我想**引擎替我跟踪每个订单从提交到终态的完整状态机（含部分成交、修改、撤销、过期），**以便**策略只响应事件而不自建状态簿。
验收：ExecutionEngine 产出 OrderAccepted/Filled/Rejected 等事件序列，Cache 中订单状态与 venue 回报一致（FR-003）。

## US-005 集中风控预检
**作为**自营交易团队，**我想**所有订单在发出前经过统一风控引擎检查（额度、价格偏离、频率），**以便**在引擎层拦截违规指令。
验收：RiskEngine 对每条 TradingCommand 预检，违规被拒并发布事件，风控规则可配置（FR-008）。

## US-006 实时组合核算
**作为**量化研究员，**我想**任一时刻查询未实现/已实现盈亏、敞口与账户余额，**以便**在策略内做仓位与风险决策。
验收：Portfolio 基于事件流增量更新，analyzers 产出完整绩效指标（FR-009、FR-012）。

## US-007 崩溃恢复
**作为**量化开发者，**我想**节点崩溃重启后自动恢复订单、仓位、账户状态，**以便**7×24 运行不丢状态。
验收：基于事件溯源重放恢复（crash-only 设计），恢复后 Cache 状态与崩溃前一致（FR-004、FR-005）。

## US-008 历史数据回放研究
**作为**量化研究员，**我想**接入高质量历史数据源（Databento、Tardis）并按需回放，**以便**在真实微观结构上测试策略。
验收：databento/tardis 适配器提供历史数据加载，回测可按时间推进回放（FR-014、FR-013）。

## US-009 自定义数据与指标
**作为**量化研究员，**我想**把自有数据（信号、外部特征）注入事件流并使用内置技术指标，**以便**在同一回测框架内融合多源信息。
验收：custom data 可注册进 DataEngine，indicators 库（crates/indicators）在策略中可用（FR-015、FR-006）。

## US-010 Rust 原生策略
**作为**性能敏感的量化开发者，**我想**完全用 Rust 编写策略与组件（不经 Python），**以便**关键路径零桥接开销。
验收：`crates/trading`、`crates/strategies`（Rust 端）支持纯 Rust 组装；Python 仅为可选控制面（FR-007、NFR-001）。
