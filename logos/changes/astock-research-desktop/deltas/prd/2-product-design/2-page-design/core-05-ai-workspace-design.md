# 策略研究工程台设计（原 AI 工作台重构）

## 为什么
研究过程需要工程化流水线：需求、设计、实现、调试验证、交易计划逐级可追溯。以研究项目为工作单元，把需求文档、设计图、策略版本、调试证据与验证结论连接到可复现计算；保留 A股研究、Windows/Linux 原生 Rust GUI、不自动下单的产品边界。本文件由 core-05-ai-workspace-design.md 重构而来，多 Agent 协作从主导航并入需求页协作记录。

## 概念辨析：调试、回测、验证、验证交易计划不是一码事
| 活动 | 回答的问题 | 数据规模 | 输出物 |
|---|---|---|---|
| 调试策略 | 为什么这笔订单被拒绝？信号用了哪个时点的数据？——正确性问题 | 小样本、事件级 | 事件轨迹、源码定位、修复版本 |
| 回测 | 这套规则在历史上表现如何？——统计表现问题 | 长历史批量模拟 | 净值曲线、回撤、换手、成本 |
| 验证策略 | 结果可信吗？——下结论的闸门：正确性验证（无前视、时点正确，手段是调试）+ 有效性验证（样本外、参数稳健，手段是回测） | 综合 | 验证清单结论与假设审查记录 |
| 验证交易计划 | 下一个交易日具体做什么？清单可信吗？——前向一次性核对，不是历史模拟 | 最新一个时点 | 目标持仓核对、现金/整手/费用约束检查、导出清单 |

关系链：需求 → 设计 → 实现 → 调试（修正确性）→ 回测（统计表现）→ 验证（下结论）→ 交易计划（最新时点前向核对）→ 人工执行。四者共用同一份冻结的策略版本与计算口径。此辨析直接决定页面边界与文案。

## 本轮交付与能力边界
交付独立离线 HTML 工程台，作为原生 GUI 的交互设计参考。Agent 使用预设角色产物，不连接大模型；Python 为可编辑代码示意，不在浏览器执行。回测由明确标注的固定合成样本和 JavaScript 演示模拟器实际计算，不代表 Nautilus 引擎或真实市场表现。状态保存在当前页面内存，刷新重置；实验与计划可导出。

## 信息架构（六页流水线）
左侧导航为需求、设计、开发、调试、验证、交易计划；底部共享入口链接既有数据中心、股票池、策略库和人工交易计划。顶部持续显示需求版本、流程版本、代码版本与验证结论；每页顶部步骤条展示流水线进度。右侧为检查器与项目上下文，底部是可见操作日志。

1. **需求**：维护需求文档——正文、验收标准、结构化参数（投入比例、最低成交额），确认生成需求版本 R1/R2…；右侧 Agent 协作记录保留预设角色产物、依赖层、预算、取消与重试语义。上游变更使下游产物过期，保留已运行实验的冻结输入。
2. **设计**：从策略处理逻辑自动生成两张 SVG 图——系统处理流程图（数据→过滤→信号→仓位→成交→指标，节点可点选查看输入/输出/代码行）与调仓周期时序图（数据服务/股票池过滤/信号形成/仓位计算/模拟成交/指标计算六条生命线，消息编号①–⑥，信号日与执行日分隔线强调时点边界）。流程参数编辑保存生成新流程版本；设计说明会话内保存。
3. **开发**：代码编辑、预置映射检查、不可变版本、审查建议应用修复。只有预置且完整匹配的两种代码示意可映射至演示模拟器。
4. **调试**：事件轨迹按日期、股票、节点筛选；单步或播放，暂停并定位源码行；显示可见时间、输入、条件、目标股数、订单拒绝或成交及账户状态。定位为正确性验证工具。
5. **验证**：回测实验记录、净值比较、首个分歧定位、JSON 导出；验证清单四项（无前视时点、成本与跳空已建模、拒绝原因已定位、样本边界已声明）逐项人工标记通过/存疑，汇聚为版本结论。只有结论「通过」的版本可进入交易计划。
6. **交易计划**（S20）：选择验证通过的冻结版本，手工录入现金与持仓，按期末参考价计算目标股数并核对现金、整手、可卖约束；导出带演示标识的 CSV。页面明示这不是回测。

## 场景映射
S17 → 需求页（需求版本与协作记录）；S18 → 设计页与开发页（流程图/时序图生成、流程版本、代码版本）；S19 → 调试页与验证页（事件调试、实验比较、验证清单）；S20 → 交易计划页（验证版本的前向核对与导出）。编号 S20 占用 scenario_counter 第 20 号，计数器推进至 21。

## S19 沿用机制
合成样本 SYN-A、SYN-B、SYN-C；初始资金 10000 元，信号日 2026-01-05，下一日开盘成交；买入单位100股、单笔费用5元仅为演示假设。A 前收盘10元，开盘10.1元，收盘10.4元，下一日收盘10.8元；B/C 因示例信号或成交额被过滤。默认投入比例100%、最低成交额1000万元。v1 申请1000股，成本10105元，拒绝后净值10000；v2 买900股，现金905元，最终净值10625元，收益6.25%。没有卖出和年化指标。实验冻结需求、流程、源码、数据与模拟器版本；不允许修改历史运行参数。

## 视觉与状态
黑色为主体的玻璃态：近黑蓝黑底 `#0a0d14` 叠加靛蓝/紫径向微光；面板 `rgba(255,255,255,.045)` + `backdrop-filter:blur(14px)` + 半透边框与内顶高光；主色靛蓝 `#6b7aee`、点缀紫 `#a78bfa`（避开绿色系）；提供浅色备选主题。图形使用 SVG 与 CSS，离线无第三方资源。适配1100与1440宽窗口，可见键盘焦点、文本状态与空态。任务完成与取消通过状态栏提示；输入错误留在编辑区。

## 实现映射与后续生产设计
保持 egui/eframe Rust GUI 方向。GUI 调用项目服务；协调器只调受限工具；研究 worker 执行确定性引擎；数据库保存版本和运行清单，大事件文件以追加方式记录。模型不能写净值或伪造工具成功。Nautilus 引擎在同一 worker 线程创建、使用、销毁。生产策略语言与沙箱需单独完成接口和运行时设计，原型 Python 示例不构成选型承诺。

本轮没有生产 API、数据库迁移、部署或 smoke 变更；场景时序是本地原型的交互契约，正式 API 必须由进一步细化的时序推导。
