# AI 研究项目补充需求

本轮交付以对话为主入口的统一策略研究原型，继续适用 A 股日线、Rust 原生双平台、不自动下单的产品边界。

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-R13 | 项目内维护需求正文、验收标准与确认版本 | 对话生成草稿，直接编辑，确认新版本；旧实验保留 |
| FR-R14 | 设计说明与同源流程图、时序图 | 节点绑定条件、输入输出与源码；改变参数使旧版本过期 |
| FR-R15 | 开发、检查、修复差异与不可变代码版本 | 任意源码可保存为草稿，但不能冒称执行；只有预置示例可运行演示 |
| FR-R16 | 调试与回测实验 | 事件单步、筛选、源码定位；修复前后账户计算可复现 |
| FR-R17 | 全链路证据与来源 | 实验冻结需求、设计、代码、数据、股票池和模拟器；可导出 |
| FR-R18 | 策略验证与交易计划核对独立 | 缺失证据不通过；演示检查与正式验证分列；计划输入变化阻断旧计划导出 |
| FR-R19 | 单入口与项目隔离 | core-05 为主入口，core-03 旧锚点映射；项目切换保留各自对话与产物 |
| FR-R20 | 对话主交互、多智能体后台化 | 前端呈现一个助手、任务状态及产物卡片；取消后无产物提交，失败可重试 |
| FR-R21 | 黑色玻璃态与可用性 | 1440/1100 桌面布局、键盘焦点、无外部资源；编辑区可专注展开 |
| FR-R22 | GUI 内配置 octos LLM provider | 顶栏「模型设置」浮层：查看当前主模型、从 catalog 选择 family/model、填写 route（label/base_url/api_type）与 api_key、保存生效（后续新会话）、连通测试；api_key 仅经 RPC 内存传输，不写盘、不进日志；配置失败给出中文诊断 |
| FR-R23 | 对话隐式生成需求草稿（issue #39） | 用户以自然语言描述研究想法并命中需求草稿意图时，由真实 LLM 生成结构化需求草稿（研究目标/范围/参数/验收标准）填入草稿框，等用户编辑后确认版本；生成不经用户显式点按钮外的额外操作（隐式派发）；octos 不可用或生成失败时降级为原文入草稿框并如实标注；草稿内容不进日志文件 |
| FR-R24 | 对话流式回显与任务进度细化（issue #41） | 自由对话及 LLM 任务执行期间，右栏消息流以 message/delta 增量实时预览回复并标记「生成中」；turn 终态后以 `assistant_persisted` 持久化产物为准替换落定，预览与持久化不一致时以持久化为准；octos 未发 delta 帧时诚实降级为一次性回显；对话任务条显示增量接收状态；多 Agent 任务条在终态计数之外显示每路子任务状态（执行中/已完成/失败） |

对话主入口经 octos 接入真实模型（online-chat-llm-config-20261012；fix-issues-38-39-20261013、fix-issues-40-41-20261013 修订）：意图路由保持确定性动作优先（实验、报告、计划等本地动作不经 LLM），自由问答由真实 LLM 经 OUP 接线回复，**回复以 message/delta 增量实时预览、turn 终态以 `assistant_persisted` 持久化产物落定**（issue #41；RD-018 落盘口径不变）；**需求草稿意图（DraftRequirement）由真实 LLM 隐式生成结构化草稿**（issue #39）；octos 不可用（profile 缺失/连接失败）时诚实降级为离线预设意图交互并在 UI 如实标注。**agent 会话与 LLM 配置的数据/实例/工作区路径一律绝对化（canonicalize）后传入 octos 子进程**（issue #38：相对路径在子进程 cwd 下二次解析致 profile store 错位）。**各路由画布的滚动容器与文本编辑控件使用路由命名空间下的唯一 widget ID，切换路由不得共享 egui 持久化状态**（issue #40：全路由共用 id_salt 致需求草稿文本泄漏至实验页）。合成样本不能提供真实市场、样本外或稳健性证据；正式验证保持“证据不足”。仅允许通过当前版本演示检查后生成明确标注的演示计划。
