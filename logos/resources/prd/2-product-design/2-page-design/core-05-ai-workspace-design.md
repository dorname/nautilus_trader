# 原生 AI A股研究工作台设计

## 为什么
研究过程需要可追溯的需求、研究证据、处理流程、策略版本、调试记录与实验。以研究项目为工作单元，把多 Agent 的产物连接到可复现计算；保留 A股研究、Windows/Linux 原生 Rust GUI、不自动下单的产品边界。

## 本轮交付与能力边界
交付独立离线 HTML 工作台，作为原生 GUI 的交互设计参考。Agent 使用预设角色产物，不连接大模型；Python 为可编辑代码示意，不在浏览器执行。回测由明确标注的固定合成样本和 JavaScript 演示模拟器实际计算，不代表 Nautilus 引擎或真实市场表现。状态保存在当前页面内存，刷新重置；实验可导出 JSON。

## 项目信息架构
左侧为需求、协作、流程、开发、调试、实验；底部共享入口链接既有数据中心、股票池、策略库和交易计划。中间是产物工作区，右侧是 Agent 产物与依据，底部是可见操作日志。顶部持续显示需求版本、流程版本、代码版本和数据快照。

需求文本与结构化参数分别编辑，用户明确确认结构化参数后生成需求版本；原型不承诺自动理解任意自然语言。上游变更使下游产物过期待更新，保留已运行实验和其冻结输入。所有 AI 建议均为待应用产物，不直接覆盖代码。

## S17：描述需求与多 Agent 协作
需求 Agent 产出结构化规格；数据 Agent 与策略研究 Agent 并行；流程 Agent 依赖两者；开发 Agent 依赖流程；审查 Agent 检查产物；回测分析 Agent 在实验结束后产出摘要。协调器显示依赖、状态、操作次数预算、取消和重试。原型每个步骤可观察，取消后不继续提交产物；重试重新执行当前需求版本。角色是逻辑分工，生产环境不强制每个角色独立进程。

展示已执行动作、输入引用、工具结果、产物与错误，不展示或虚构模型内部思维链。每份产物具有需求版本、角色、输入引用、时间和状态。实际生产还需模型提供方配置、超时、工具白名单、额度与沙箱；本轮不实现网络调用。

## S18：处理流程与开发
区分三张图：Agent 依赖图、策略处理流程图、实际事件轨迹。策略图包含数据→过滤→信号→仓位→成交→指标，点选节点查看输入、输出、参数及对应代码位置。固定拓扑，支持编辑最低成交额与投入比例并保存流程版本；参数影响演示计算。通用拖拽连线编辑器留待正式实现。

代码页支持编辑、检查、保存不可变版本、查看差异、应用修复。只有预置且完整匹配的两种代码示意可映射至演示模拟器，任意其他源码不能伪装为已执行。v1 使用前收盘价计算数量，v2 用次日开盘价和固定费用限制可买数量。修复必须生成新版本。

## S19：调试与实验比较
合成样本 SYN-A、SYN-B、SYN-C；初始资金 10000 元，信号日 2026-01-05，下一日开盘成交；买入单位100股、单笔费用5元仅为演示假设。A 前收盘10元，开盘10.1元，收盘10.4元，下一日收盘10.8元；B/C 因示例信号或成交额被过滤。默认投入比例100%、最低成交额1000万元。v1 申请1000股，成本10105元，拒绝后净值10000；v2 买900股，现金905元，最终净值10625元，收益6.25%。没有卖出和年化指标。

调试按日期、股票、节点筛选；单步或播放事件，暂停并定位源码行；显示可见时间、输入、条件、目标股数、订单拒绝或成交及账户状态。切换版本显示首个分歧。实验冻结需求、流程、源码、数据与模拟器版本，展示两条净值曲线、指标与可导出事件。不允许修改历史运行参数。

## 视觉与状态
沿用深色导航、浅色工作区与青绿色强调，图形使用 SVG 与 CSS，离线无第三方资源。适配1100与1440宽窗口，提供深色主题、可见键盘焦点、文本状态与空态。任务完成与取消通过状态栏提示；输入错误留在编辑区。

## 实现映射与后续生产设计
保持 egui/eframe Rust GUI 方向。GUI 调用项目服务；协调器只调受限工具；研究 worker 执行确定性引擎；数据库保存版本和运行清单，大事件文件以追加方式记录。模型不能写净值或伪造工具成功。Nautilus 引擎在同一 worker 线程创建、使用、销毁。生产策略语言与沙箱需单独完成接口和运行时设计，原型 Python 示例不构成选型承诺。

本轮没有生产 API、数据库迁移、部署或 smoke 变更；以下场景时序是本地原型的交互契约，正式 API 必须由进一步细化的时序推导。
