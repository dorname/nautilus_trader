# 策略研究工程台设计（原 AI 工作台重构）

## 为什么
以一个研究项目连接需求、设计、开发、调试、实验、验证与交易计划。用户通过持续对话推动流程，直接操作文档、图表和编辑器；后台协作仅呈现任务状态和可核查产物。

## 信息架构
唯一主入口 core-05-ai-workspace-prototype.html。左侧为项目切换、研究阶段与数据/股票池/策略库，是全应用唯一导航（不再设重复的产物标签页）；中间为产物工作区；右侧为助手对话、任务卡片与输入，调用与发起 Agent 的动作集中在右手侧。顶部展示项目与版本、演示范围。支持产物专注模式；1100 宽下可展开工作区再返回对话。
原 core-03 变为兼容导向：data→data、pool→pool、develop→develop、research/compare→experiments、plan→plan。兼容页不维护第二份业务状态。

## 对话与任务
快捷提示覆盖生成需求、设计、代码、实验、验证、交易计划和概念解释。自由输入按明确的演示意图识别；不能理解的输入显示能力边界并提供动作选择，不伪造通用模型回复。研究目标经对话转为待确认草稿，用户可直接编辑；对话卡片打开对应产物。
所有修改当前确认规格的动作都生成新版本。代码修复先展示旧/新差异，点击应用后检查并保存。后台任务具备执行中、已取消、失败、完成状态；提供取消、重试及一次失败模拟供交互检查。原型无模型联网请求。

## 产物与联动
需求：正文、验收标准、投入比例、成交额阈值，可编辑、确认、查看历史。
设计：维护说明和参数；流程图与时序图由共同节点结构生成；点选节点查看输入输出及对应源码行。确认新设计使代码旧引用过期。
开发：源码编辑、预置示例识别、不可变版本、修复差异、保存与运行。代码编辑不改变已保存版本。
调试：选择实验、事件表、节点筛选、单步与播放暂停，冻结源码定位；回放不冒称实时断点调试。
回测实验：账户指标、最近两次曲线、冻结清单、事件分歧和 JSON 导出。
验证：逐项展示演示检查证据；正式验证的真实数据、样本外、稳健性为未运行。当前版本或资源改变后报告过期。
交易计划：独立数据/账户输入、生成草稿、核对、确认导出；计划与回测概念解释常驻。
数据：合成快照覆盖、质量说明、模拟更新；股票池：搜索、流动性筛选、保存规则；策略库：浏览当前项目不可变版本并载入研究。

## 视觉与可访问性
设计原则：功能好用、操作简单优先于界面丰富；导航和功能入口只保留一处，不为"看起来完整"增加重复控件。视觉风格对齐 SecondBrain 整体布局原型的"纯黑科技 v3"：#0a0a0a 纯黑基底叠加绿色（左上）与青色（右下）环境柔光，主色绿 #22C55E、辅助青 #06B6D4；侧栏与主区为悬浮圆角玻璃卡片，面板统一三层玻璃（glass / glass-soft / glass-strong，backdrop-filter 模糊 + 饱和度提升 + 顶部高光）；导航激活项带绿色指示条与辉光；数字、标签、分组标题使用等宽字体。阅读、代码区域采用实色深底；图形为离线 SVG。文字状态不只依赖颜色，键盘焦点清晰，尊重减少动态效果设置。1440×1000 与 1100×900 可操作，无页面水平溢出。

## 概念辨析
调试排查实现正确性；回测是历史模拟；策略验证汇总正确性、样本外与稳健性证据；交易计划核对最新账户与具体调整约束。反复在历史日期生成并模拟执行计划属于策略回测，核对下一份计划不属于回测。

## 本轮边界
离线单文件、内存会话刷新重置、预设对话和固定合成计算；不执行任意 Python、不连接真实多智能体或行情、不自动下单。可下载文档、源码、实验与演示计划。HTML 为后续 Rust GUI 设计参考，无生产 API 或数据库变更。浏览器检查只记录在变更目录，不能作为生产验收通过。


## 业务阶段与下一步（S17～S20）

项目概览按当前有效引用计算阶段，不用历史产物数量推断完成。每一阶段给出原因和可点击的下一步；历史实验始终保留。

| 条件（从上到下匹配） | 状态与下一步 |
|---|---|
| 任务运行中 | 展示任务名称，等待完成或取消 |
| 需求未确认 | 确认研究需求 |
| 设计缺失或引用旧需求 | 保存与当前需求匹配的设计 |
| 当前策略缺失或上游已改变 | 检查并保存当前策略版本 |
| 当前版本没有实验 | 运行合成实验 |
| 当前版本实验存在，报告缺失或过期 | 生成当前版本验证报告 |
| 演示检查失败 | 打开事件调试，定位失败证据 |
| 演示检查通过，计划缺失或输入变化 | 生成演示计划草稿 |
| 计划未核对或存在约束问题 | 核对账户与计划，显示具体问题 |
| 计划核对通过 | 确认导出演示清单；正式验证仍为证据不足 |

### 草稿与生效边界
需求正文、验收标准、需求参数、设计说明与参数、源码编辑均为草稿。离开编辑页后，工作区持续提示哪些草稿尚未确认或保存。运行仍引用已保存的冻结版本，不能把草稿编辑暗示成已经生效。确认需求、保存设计、保存股票池或更新数据后，旧版本按引用关系过期；历史结果不改写。

### 实验可比性
最近两次实验先比较冻结的需求、设计、数据、股票池和模拟器。只有这些输入完全一致时，才允许把代码变化作为受控比较因素。任一输入不同均列出差异，曲线仍可查看，但标注“仅并列查看，不作代码效果归因”；同一代码重复运行标为重复实验。固定资金、日期、费用属于当前模拟器假设，后续可配置时也必须纳入比较。

### 验收与演示边界
ST-S17-15：给定不同研究阶段或上游变化，概览下一步与当前有效证据一致；有历史实验但当前版本无实验时仍提示运行。
ST-S18-14：编辑草稿后切换页面，提示未生效范围；原冻结输入保持不变；确认后显示过期与恢复入口。
ST-S19-14：同输入修复比较可归因；跨参数或快照比较列出差异；原实验内容保持不变。
现有 ST-S20-11～13 继续约束计划资金、可卖数量、时效、核对与导出。本轮不将演示通过升级为正式策略通过。
