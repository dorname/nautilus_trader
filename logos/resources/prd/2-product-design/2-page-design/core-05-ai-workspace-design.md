# 策略研究工程台设计（原 AI 工作台重构）

## 为什么
以一个研究项目连接需求、设计、开发、调试、实验、验证与交易计划。用户通过持续对话推动流程，直接操作文档、图表和编辑器；后台协作仅呈现任务状态和可核查产物。

## 信息架构
唯一主入口 core-05-ai-workspace-prototype.html。左侧为项目切换、研究阶段与数据/股票池/策略库，是全应用唯一导航（不再设重复的产物标签页）；中间为产物工作区；右侧为助手对话、任务卡片与输入，调用与发起 Agent 的动作集中在右手侧。顶部展示项目与版本、演示范围。支持产物专注模式；1100 宽下可展开工作区再返回对话。
原 core-03 变为兼容导向：data→data、pool→pool、develop→develop、research/compare→experiments、plan→plan。兼容页不维护第二份业务状态。

## 对话与任务
快捷提示覆盖生成需求、设计、代码、实验、验证、交易计划和概念解释。自由输入按明确的演示意图识别；不能理解的输入显示能力边界并提供动作选择，不伪造通用模型回复。研究目标经对话转为待确认草稿，用户可直接编辑；对话卡片打开对应产物。
所有修改当前确认规格的动作都生成新版本。代码修复先展示旧/新差异，点击应用后检查并保存。后台任务具备执行中、已取消、失败、完成状态；提供取消、重试及一次失败模拟供交互检查。原型无模型联网请求。

## 产物与联动
需求：正文、验收标准、投入比例、成交额阈值，可编辑、确认、查看历史。
设计：维护说明和参数；流程图与时序图由共同节点结构生成；点选节点查看输入输出及对应源码行。确认新设计使代码旧引用过期。
开发：源码编辑、预置示例识别、不可变版本、修复差异、保存与运行。代码编辑不改变已保存版本。
调试：选择实验、事件表、节点筛选、单步与播放暂停，冻结源码定位；回放不冒称实时断点调试。
回测实验：账户指标、最近两次曲线、冻结清单、事件分歧和 JSON 导出。
验证：逐项展示演示检查证据；正式验证的真实数据、样本外、稳健性为未运行。当前版本或资源改变后报告过期。
交易计划：独立数据/账户输入、生成草稿、核对、确认导出；计划与回测概念解释常驻。
数据：合成快照覆盖、质量说明、模拟更新；股票池：搜索、流动性筛选、保存规则；策略库：浏览当前项目不可变版本并载入研究。

## 视觉与可访问性
设计原则：功能好用、操作简单优先于界面丰富；导航和功能入口只保留一处，不为"看起来完整"增加重复控件。视觉风格对齐 SecondBrain 整体布局原型的"纯黑科技 v3"：#0a0a0a 纯黑基底叠加绿色（左上）与青色（右下）环境柔光，主色绿 #22C55E、辅助青 #06B6D4；侧栏与主区为悬浮圆角玻璃卡片，面板统一三层玻璃（glass / glass-soft / glass-strong，backdrop-filter 模糊 + 饱和度提升 + 顶部高光）；导航激活项带绿色指示条与辉光；数字、标签、分组标题使用等宽字体。阅读、代码区域采用实色深底；图形为离线 SVG。文字状态不只依赖颜色，键盘焦点清晰，尊重减少动态效果设置。1440×1000 与 1100×900 可操作，无页面水平溢出。

## 概念辨析
调试排查实现正确性；回测是历史模拟；策略验证汇总正确性、样本外与稳健性证据；交易计划核对最新账户与具体调整约束。反复在历史日期生成并模拟执行计划属于策略回测，核对下一份计划不属于回测。

## 本轮边界
离线单文件、内存会话刷新重置、预设对话和固定合成计算；不执行任意 Python、不连接真实多智能体或行情、不自动下单。可下载文档、源码、实验与演示计划。HTML 为后续 Rust GUI 设计参考，无生产 API 或数据库变更。浏览器检查只记录在变更目录，不能作为生产验收通过。

## 演示原型与生产桌面映射

本 HTML 原型为演示交互设计（合成数据、内存会话），生产桌面 `crates/research-desktop` 以研究协调器协议为真实接口。二者在多数页面同构，但**数据中心与股票池两页存在有意分叉**（RD-004）：

| 页面 | 原型（演示交互） | 生产桌面（协调器协议 UI） | 验收对齐基准 |
|---|---|---|---|
| 数据中心 `#data` | 「当前合成数据快照」KV + 「价格与信号样本」fixture 表 + 「模拟更新快照」 | 「数据导入」（CSV 路径 + 价格口径）+ 「快照清单」（协调器 snapshot 列表）；通达信 / TickFlow 为后续生产能力 | 不对 HTML 像素对齐；以 S11 数据快照契约与场景测试为准 |
| 股票池 `#pool` | 搜索框 + 市场 select + 最低成交额 + 「保存股票池规则」+ 候选样本表 | RuleAST JSON 编辑 + as_of / 严格模式 / 固定成员 + 「预览」（协调器任务）+ 预览结果列表 | 不对 HTML 像素对齐；以 S12 股票池筛选契约与场景测试为准 |

分叉理由：原型资源页用于演示筛选交互概念；生产桌面直接暴露协调器真实能力（导入、预览任务），回退为演示壳会丢失生产价值。若未来需要将演示筛选 UI 映射到协调器 RuleAST，须单独立变更提案。除上述两页外，其余页面验收仍以本原型为视觉与信息架构权威。


## 业务阶段与下一步（S17～S20）

项目概览按当前有效引用计算阶段，不用历史产物数量推断完成。每一阶段给出原因和可点击的下一步；历史实验始终保留。

| 条件（从上到下匹配） | 状态与下一步 |
|---|---|
| 任务运行中 | 展示任务名称，等待完成或取消 |
| 需求未确认 | 确认研究需求 |
| 设计缺失或引用旧需求 | 保存与当前需求匹配的设计 |
| 当前策略缺失或上游已改变 | 检查并保存当前策略版本 |
| 当前版本没有实验 | 运行合成实验 |
| 当前版本实验存在，报告缺失或过期 | 生成当前版本验证报告 |
| 演示检查失败 | 打开事件调试，定位失败证据 |
| 演示检查通过，计划缺失或输入变化 | 生成演示计划草稿 |
| 计划未核对或存在约束问题 | 核对账户与计划，显示具体问题 |
| 计划核对通过 | 确认导出演示清单；正式验证仍为证据不足 |

### 草稿与生效边界
需求正文、验收标准、需求参数、设计说明与参数、源码编辑均为草稿。离开编辑页后，工作区持续提示哪些草稿尚未确认或保存。运行仍引用已保存的冻结版本，不能把草稿编辑暗示成已经生效。确认需求、保存设计、保存股票池或更新数据后，旧版本按引用关系过期；历史结果不改写。

### 实验可比性
最近两次实验先比较冻结的需求、设计、数据、股票池和模拟器。只有这些输入完全一致时，才允许把代码变化作为受控比较因素。任一输入不同均列出差异，曲线仍可查看，但标注“仅并列查看，不作代码效果归因”；同一代码重复运行标为重复实验。固定资金、日期、费用属于当前模拟器假设，后续可配置时也必须纳入比较。

### 验收与演示边界
ST-S17-15：给定不同研究阶段或上游变化，概览下一步与当前有效证据一致；有历史实验但当前版本无实验时仍提示运行。
ST-S18-14：编辑草稿后切换页面，提示未生效范围；原冻结输入保持不变；确认后显示过期与恢复入口。
ST-S19-14：同输入修复比较可归因；跨参数或快照比较列出差异；原实验内容保持不变。
现有 ST-S20-11～13 继续约束计划资金、可卖数量、时效、核对与导出。本轮不将演示通过升级为正式策略通过。

## 视觉保真验收口径

生产桌面（egui）相对本原型（CSS）的视觉验收按两张表执行：**必须像素/交互对齐**项不一致即验收不通过；**平台近似可接受**项以近似口径为准，不得假装像素级一致，也不得再作为缺口提出。

### 必须像素 / 交互对齐

| 原型能力 | 验收要求 | 实现锚点 |
|---|---|---|
| `.brand-mark`：29×29、圆角 9、145° 线性渐变 `#4ade80→#16a34a`、外圈辉光、字色 `#03130a` | 渐变角度与起止色一致；辉光可见；「研」字居中 | `theme::paint_brand_mark` |
| `.nav button.active:before`：2px 绿色指示条 + 辉光 | 激活态左缘指示条 + 多层辉光；非激活无 | `app::nav_item` |
| `@media max-width:1200px` / `900px` 断点 | 三档布局：舒适档侧栏 212/对话栏 360；窄档（≤1200）178/320；图标档（≤900）侧栏 65 纯图标、隐藏品牌名与计数 | `layout::plan_for_width`（UT-S15-08） |
| 文字四层级 + 等宽数字/标签 | 颜色层级与等宽字体使用一致 | `theme::TEXT/MUTED/FAINT`、等宽 FontId |
| 键盘焦点清晰、文字状态不只依赖颜色 | 焦点环可见；状态同时有图标/文字承载 | 各交互控件 |

### 平台近似可接受（egui 即时模式无对应 CSS 原语）

| 原型能力 | 近似口径 | 代码注释位置 |
|---|---|---|
| `backdrop-filter: blur(…)` 真实毛玻璃 | 半透明面板色 + 顶部高光描边 | `theme.rs` 模块头 |
| 双径向环境柔光 | 角点色网格线性插值 | `theme::paint_ambient` |
| `box-shadow` 导航辉光 / 品牌 glow | 多层透明度递减叠加 | `app::nav_item` / `theme::paint_brand_mark` |
| `prefers-reduced-motion:reduce` 关闭动画 | 任务状态指示器遵循系统减少动态效果偏好，开启时静止；详见下节 | 本节即口径 |

## RD-003 关闭证据与动态效果处理

当前任务状态指示器存在时间驱动旋转，不能以“无动画”作为减少动态效果的关闭依据。启动时读取平台的减少动态效果偏好，读取失败默认减少动态效果；提供可访问的显式选择。减少动态效果开启时保持静态任务指示、状态文本与取消入口，后台轮询继续运行。关闭时允许原有旋转。检测只执行一次，不阻塞 GUI 帧循环。

品牌、导航激活辉光、900/901/1200/1201px 布局、内嵌中文字体由 UT-S15-12、ST-S15-16、UT-GUI-05、UT-GUI-06 与既有 UT-S15-08、UT-GUI-04 留存证据。保存原型与 egui 渲染对照图，并记录后端、尺寸与局限。离屏验证不能声称原生可见窗口通过。

浅色主题按既有 RD-002 合并决策关闭；平台模糊、环境柔光和阴影按现行近似口径陈述。GitHub 关闭说明必须逐项链接测试结果、截图与设计决策，不能以提案已归档替代证据。

## 原生窄窗口可达性

默认窗口保持 1440×900；原生最小窗口调整为 880×720，使用户可实际进入 ≤900px 图标栏。此前 core-02 的 1100×720 下限由本节取代；不能以离屏可渲染但原生窗口不可达作为断点验收通过。UT-S15-08 与 ST-S15-16 必须断言原生窗口下限及 880px 最小窗口布局。

## 生产桌面在线对话与模型设置（online-chat-llm-config-20261012）
> 本节为生产桌面（`crates/research-desktop`）行为口径；上方「本轮边界」描述的是 HTML 演示原型本身，不随本节改动。

### 自由对话在线化

- 对话输入经意图路由：确定性业务动作（运行实验、生成报告、计划生成/核对/导出、新建项目等）保持本地执行不经 LLM；「生成策略设计 / 生成策略代码」维持既有真实 LLM 路径；**其余自由问答由真实 LLM 经 octos（OUP stdio）回复**，任务条出现「对话回复 ·」进度行，回复经 `assistant_persisted` 进入消息流。
- 非流式口径：turn 完成一次性回显；流式 delta 渲染为后续提案。
- 诚实降级：octos 不可用（profile 缺失 / 连接失败 / 版本不匹配）时回退离线预设意图引擎，右栏底部标注保持「离线预设交互 · 未接入模型」；接线可用时标注改为「AI 助手 · octos 已接线」。顶栏「演示环境」tag 保留（数据仍为合成样本，与模型接线无关）。

### 模型设置浮层

- 入口：顶栏「运行记录」旁新增「模型设置」按钮。
- 浮层内容：当前主模型（family / model / label）；catalog 拉取的 family、model 下拉；route 表单（label、base_url、api_type: openai/anthropic）；api_key 密码输入框（显示占位符，不回显）；操作：保存（upsert + set_primary）、连通测试、关闭。
- 安全：api_key 仅经 OUP RPC 内存传输（SecretString 语义），desktop 不写盘、不进日志文件、不入运行记录浮层。
- 生效口径：保存写入 octos profile，后续新 agent 会话生效；进行中的会话不热切换。
